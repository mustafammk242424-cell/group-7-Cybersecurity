# **Chapter 4: Agile Project Management**

## **4.1 Agile Methodology Overview**
To ensure the timely and high-quality delivery of the "Web Application Security Risk Detection and Remediation Demonstration System" (Topic 15), our team adopted the **Agile Scrum framework**. Unlike traditional waterfall models, Agile allows for iterative development, which is crucial for a cybersecurity project where threat landscapes and standards (e.g., the transition from OWASP Top 10: 2021 to 2025) evolve rapidly. 

We utilized **Jira** for Product Backlog management and Sprint planning, and **GitHub** for version control. The project is divided into two-week Sprints, each concluding with a Sprint Review and Retrospective to ensure alignment with the project scope and grading rubrics.

## **4.2 User Stories**
User stories define the system requirements from the perspective of the end-users and stakeholders. The following three core user stories guided our Phase 2 development:

1. **Vulnerability Detection (Red Team Perspective)**
   * **As a** security tester, 
   * **I want to** scan the target web application (OWASP Juice Shop) using automated tools and manual penetration testing techniques, 
   * **So that** I can identify and document vulnerabilities mapped to the OWASP Top 10: 2025 standard.
2. **Remediation Demonstration (Blue Team/Developer Perspective)**
   * **As a** web developer, 
   * **I want to** view a side-by-side comparison of vulnerable code and remediated code (e.g., Fail-Open vs. Fail-Closed mechanisms), 
   * **So that** I can understand the root cause of the security flaws and implement effective patches.
3. **Risk Visualization (Stakeholder Perspective)**
   * **As a** project stakeholder, 
   * **I want to** access a centralized dashboard displaying the detection results and remediation status, 
   * **So that** I can evaluate the overall security posture of the demonstration system without needing deep technical expertise.
